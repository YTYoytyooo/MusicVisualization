# 音频运动特征

`studio.motion_features.load_motion_features(project_path, progress=None, cancel=None)`
从项目内已有音频补齐轻量运动驱动特征。只读音频，不重新推理、不调用 MFCC/chroma，也不读取或修改原始预测、修订与 project.json。

## 返回值与时间含义

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| times_us | int64 一维数组 | 从 0 起，每 100000 微秒一个点 |
| rms | float64 一维数组 | 对应 0.1 秒区间全部声道样本的原始均方根；末段截到音频结尾 |
| onset | float64 一维数组 | 相邻幅度频谱的正差 L2 范数；第一点为 0 |
| activity | float64 一维数组，0–1 | RMS / max(本曲 RMS 的 95 分位数, 0.08)，截到 0–1 |
| pulse_strength | float64 一维数组，0–1 | 去除频谱差中位背景及 0.002 小变化后的脉冲，并加绝对 RMS 门控 |
| step_us | int | 100000 |
| audio_sha256 / key / kind | str | 音频摘要、缓存键、audio-rms-spectral-flux-v1 |

数组长度取真实音频时长 / 0.1 秒的向上取整，不依赖模型输出长度。消费者按时间匹配，而不是默认两种数组行数相等。

SoundFile 每次仅读一个 0.1 秒块。时间边界用整数比率计算，11025 Hz 等非整数 hop 的采样率不会累计漂移。RMS 取声道能量平均，不先合成单声道，反相立体声不会被误判为静音。

频谱使用固定 2048 点 FFT；Hann 窗支持长度为 min(2048, 一个完整 hop 的样本数)，尾部不足一个窗口时补用前面已读取的样本，不补未来数据。不同声道幅度按能量合成；只有相对上一块增加的频谱进入 onset。它是音频变化提示，不是节拍检测器，也不是情绪预测。0.1 秒采样会限制极短瞬态的表达。

pulse_strength 的归一化分母至少 0.04，额外乘以 min(RMS / 0.08, 1)。因此静音、恒定信号和相位数值小误差不会被曲内归一化放大成强脉冲；非常轻的音频也不会因为“是本曲最大值”而显示成强活动。RMS 是线性样本幅度，不冒充 LUFS 或感知响度。

## 缓存和恢复

缓存仅写入项目新增的 `motion_features/` 目录，使用独立目录写锁，不锁或改写正式修订。键包含音频 SHA-256、模块内容和全部配置、numpy/soundfile/libsndfile 版本以及音频格式信息。

NPZ + JSON 成对保存；读取检查摘要、身份、成员名单、分配前 NPY 头、形状、类型、时间轴、有限值与取值范围，禁用 pickle。坏缓存移动到 `invalid-<uuid>/` 保留后重建。新结果先写临时文件，发布前复核音频摘要和代码指纹；中途变化则拒绝发布。新代码文件与进程中加载的模块不一致时要求重启，避免把旧进程计算误标为新版本。

取消回调返回 True 时抛出 `MotionFeatureCancelled`，未发布数据不会成为有效缓存。progress 默认接收 `(stage, fraction)`；声明 `accepts_details = True` 的回调另收到 `{done, total, unit}`。同目录已有写入者时沿用工作台锁语义，立即报告忙碌，让调用方稍后重试。

新增 `tests/test_motion_features.py` 覆盖静音、静态信号、节奏/反相立体声、时间对齐、原数据保护、缓存复用/损坏重建/校验、取消、输入中途变化与写锁。测试由主任务统一执行；本模块开发步骤未自行启动验证进程。
