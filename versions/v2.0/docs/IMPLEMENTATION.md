# 工程实施与任务清单

## 目标

音乐一次分析后，可以修改指定时间点或区间的情绪、视觉数值，创建可追溯修订并重新生成视频。
升级版与旧项目完全隔离；不覆盖已安装依赖、模型、音频或旧视频。

## 架构与职责

| 模块 | 职责 |
|---|---|
| `main.py` | 唯一命令入口，惰性载入重量依赖 |
| `studio/store.py` | 原始数据、哈希、音频副本、写锁、原子保存、修订 |
| `studio/timeline.py` | 编辑协议、冲突检查、整数时间、纯函数求值 |
| `studio/pipeline.py` | 分析、缓存、规划、编码、逐帧数据与视频 |
| `studio/jobs.py` | 单工作队列、隐藏子进程、持久进度、取消、身份核验 |
| `studio/server.py` | 本机HTTP、鉴权、媒体分段读取、项目API |
| `web/` | 中文项目/版本/曲线/数值/输出工作台 |
| `emotion_model.py` | 保留模型结构与权重兼容，修正窗口对齐 |
| `mcts.py` / `renderer.py` | 原视觉引擎，新增独立种子与错误检查 |
| `prediction_overlay.py` | 原始/生效对比、共同zoom、全范围图、2秒高亮 |

处理顺序：原始预测 → 情绪编辑 → MCTS规划 → 逐帧插值 → 视觉编辑 → 同一参数对象写入CSV并渲染。

原方案的 FastAPI 是可选技术建议。当前机器未安装，首版使用标准库本机HTTP适配层，保持API契约，
不为界面改动已有Python环境。业务层与HTTP独立，后续可替换框架。

## 数据契约

- 项目 schema_version=1；音频使用内容哈希，模型和原始预测记录SHA-256。
- 原始数组 N×5，顺序 V/A/Energy/Tension/Brightness，范围[-1,1]。
- 修订有 id/parent/analysis_sha256/edits/sha256，旧版本永不覆盖。
- 编辑 layer=emotion|visual；情绪仅V/A，视觉为八个现有字段。
- operation=point_target|interval_set|interval_offset。
- 点目标有time_us，区间有start_us/end_us；过渡transition_in_us/transition_out_us。
- interpolation=linear|smoothstep|smootherstep；缺省的旧记录按linear解释，新界面默认smootherstep，不重写历史修订。
- 编辑值必须有限；同字段影响范围重叠拒绝；禁用操作不生效。
- 恢复历史是基于最新修订另存新快照，不覆盖当前版本。
- 帧数ceil(duration×fps)，时间由index/fps计算；音频补齐不足一帧的尾部。
