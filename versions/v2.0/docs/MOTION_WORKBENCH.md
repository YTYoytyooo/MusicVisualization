# 多模式运动工作台

这次升级增加的是独立的“粒子怎样运动”编辑层。原始模型预测仍然只读；可以保留同一份音乐分析结果，调整运动形态后再次生成视频。

## 从旧项目开始

1. 启动工作台，在左侧选择已有音乐项目。
2. 在右侧“运动形态与区间覆盖”中，把“运动引擎”从“旧引擎 · 保持原效果”切换为“多模式 · 情绪驱动”。内部名称分别是 `legacy` 和 `flow-v1`。
3. 等待中间下方“粒子运动轨道”显示“自动运动规划已就绪”。上轨是自动模式，下轨是人工覆盖后的生效模式；点击轨道可以跳转歌曲时间。
4. 先听音乐、查看各段，再添加需要人工干预的运动区间。当前时间的模式、混合权重和参数会显示在轨道下方。

旧项目以及不含 `motion` 配置的历史修订默认使用旧引擎。打开旧项目不会自动升级其效果；切换回旧引擎时，已填写的运动覆盖会保留但不生效。保存后才能让新的配置进入正式修订。

## 九种模式与自动选择

| 界面名称 | 标识 | 运动特征 |
| --- | --- | --- |
| 轻盈上升 | `rise` | 默认向上运动，可改方向 |
| 缓慢下沉 | `fall` | 默认向下运动，可改方向 |
| 环流绕圈 | `orbit` | 围绕中心沿较稳定的圆形轨道运动 |
| 螺旋运动 | `spiral` | 旋转与向内/向外的径向运动结合 |
| 向外扩散 | `expand` | 默认从中心附近向外散开 |
| 向内汇聚 | `gather` | 默认由外围向中心聚拢 |
| 流星掠过 | `meteor` | 较快的定向短生命周期粒子，带渐隐轨迹 |
| 波浪平移 | `wave` | 沿主方向前进，同时做波浪偏移 |
| 湍流运动 | `turbulent` | 连续变化的局部流动方向 |

自动模式使用以下输入：

- 当前生效的 Valence–Arousal，包括已经确认的人工情绪修改与可选 V/A 平滑。不会覆盖原始预测。
- 项目音频实际计算的 RMS 强弱、正频谱差、活动强度与脉冲提示，每 0.1 秒对齐一次。这些不是用模型的 Energy 字段伪造的音量。
- 有限幅度的情绪变化趋势及已有节拍时间，辅助选择切换时机。

这是可解释的美术规则：例如偏平静的状态更接近环流或波浪，偏活跃的状态可能更接近扩散、流星或螺旋。它不是固定的四象限标签，也不保证一首歌曲一定出现全部模式。导出的 `scores` 是规则匹配分数，不是模型分类概率、预测置信度或准确率。

为了避免形态频繁跳动，候选模式需要保持优势一段时间，并满足最短保持要求；转换采用平滑混合，有节拍时会短暂等待合适时机，而不是无限等待。

| 自动设置 | 范围 / 默认 | 含义 |
| --- | --- | --- |
| 自动敏感度 | 0.5–2 / 1 | 调节 A 变化趋势的有限增强，不会把平坦预测强行拉满，也不保证一定增加切换次数 |
| 最短保持 | 4–12 秒 / 6 秒 | 限制自动模式切换频率，不是保证每到该时长就切换 |
| 自动过渡 | 1–4 秒 / 2 秒 | 两种自动形态的混合时间，不能长于最短保持 |

改变 V/A、平滑或自动设置后，需要后台确认新的自动轨道；等待期间不会把旧轨道冒充新结果。仅改人工运动覆盖时，可基于已匹配的自动轨道立即计算反馈。

## 添加、修改与撤销人工运动区间

1. 选择多模式引擎，点击“＋ 添加运动区间”。
2. 指定模式、开始、结束、进入过渡、退出过渡；需要时展开“精细运动参数（可选）”。留空采用该模式预设；切换模式会将参数输入重置为预设选择。
3. 输入时，生效运动轨道与当前参数即时变化。离开输入框、按 Enter 或点“确认运动调整”，将这次有效调整确认到草稿。
4. 尚未确认时按 Esc 或“取消本次运动调整”恢复此次输入前状态。已确认操作使用“人工修改记录”中的撤销/重做；运动配置、情绪修改和平滑配置共用草稿历史。
5. 已有覆盖列在运动轨道下方，可以选择编辑、启用/禁用或删除。禁用不会删除记录。

一次连续输入不是每个字符各记一步。输入未完成、时间越界或覆盖冲突时，先修正输入或取消，不会把错误值保存成有效操作。切换项目/修订或保存后会清空当前草稿撤销栈；浏览器草稿缓存不等于正式修订。

### 区间与过渡边界

假设开始为 10 秒、结束为 16 秒，进入/退出过渡各 2 秒：

- 8–10 秒：从当时的自动运动逐渐混入人工模式。
- 10–16 秒：人工模式完全生效，包含两端目标时刻。
- 16–18 秒：逐渐退出人工模式，接回该时刻的自动运动，而不是回到 8 秒时的旧模式。
- 18 秒以后：重新使用自动控制。此前运动已经改变粒子位置，因此后续像素不必与未编辑版相同。

完整支持范围必须位于歌曲内；多个已启用覆盖的支持范围不能重叠。相邻的无过渡区间共享同一目标时刻也会冲突，不能靠记录顺序偷偷覆盖。进入或退出设为 0 表示控制立即切换，但粒子仍遵循引擎的速度跟随和转向限制，不是瞬间传送位置。

过渡可选 linear、smoothstep、smootherstep。自动过渡通常混合两种模式；人工过渡叠加自动转换时可同时出现三个成分。各权重非负且总和为 1，不能把此时的画面解释为某一个模式单独作用。

## 精细参数怎么理解

参数描述目标控制，实际粒子速度还有跟随、加速度限制和脉动影响。不是每个参数都对每种模式有相同作用。

| 参数 | 范围 | 使用说明 |
| --- | --- | --- |
| 速度 | 0–0.5，短边/秒 | 例如 1280×720 画面中 0.1 对应未加脉动的目标速度约 72 像素/秒；0 为停止目标 |
| 方向一致性 | 0–1 | 越高越贴近主要规则方向；不是多个粒子的位置完全相同 |
| 湍流强度 | 0–1 | 添加局部扰动；设为 0 仍保留上升、绕圈等主运动，不会把规则运动关掉 |
| 方向 | 0–360° | 屏幕坐标：右 0°、下 90°、左 180°、上 270°，360° 等同 0°；主要用于定向和波浪模式 |
| 中心 X / Y | 各 0–1 | 按画面宽、高归一化；0.5 / 0.5 是画面中心，主要用于环流与径向模式 |
| 半径 | 0.05–0.48，短边比例 | 0.3 在短边 720 的画面上约为 216 像素；单个粒子有固定的小幅半径差异 |
| 旋转方向 | -1 或 1 | -1 为屏幕逆时针，1 为顺时针，不接受中间数值；主要用于环流、螺旋 |
| 径向 | -1–1 | 螺旋中负值向内、正值向外，0 为无径向分量；扩散/汇聚以符号决定方向，0 回到各自默认方向 |
| 脉动强度 | 0–1 | 调节节拍/真实音频脉冲带来的速度增强，不直接修改原音频 |
| 拖尾 | 0–2 秒 | 按秒渐隐，0 不画拖尾；与情绪图中“最近 2 秒高亮”是不同设置 |

半径、中心、径向和旋转主要作用于相应运动模式，不要用方向角期待改变环流的切线运动。静音不会因曲内归一化被放大成强活动；人工指定速度则是明确覆盖自动选择，可用于有意设计静音段画面。

## 保存、局部预览与正式视频

“确认运动调整”只确认到草稿，不会覆盖已有视频。

- “生成局部预览快照”：冻结当前情绪、平滑与运动配置。选中运动覆盖时，范围包含整个进入/保持/退出，再前后各扩展 2 秒并裁到歌曲边界；未选修改时默认前 10 秒。它不创建或切换正式修订。
- “保存为新修订”：将配置作为新版本保存，不覆盖历史版本或原始预测。
- “生成当前已保存版本”：只使用该保存版本；后续修改草稿不会改变已提交任务的快照。

轨道即时反馈是控制计划，不是实时粒子视频。局部视频仍需推进此前的模拟状态或恢复兼容检查点，因此选择歌曲后半段并不一定立即出片。640×360 预览是近似草稿；正式默认 1280×720、30 FPS。

单独启用、调整或禁用运动层不重新运行 CLAP/情绪模型，运动自动规划也不依赖视觉 MCTS。实际视频仍需要原有视觉层提供颜色、亮度、粒子数量等；若匹配的视觉规划缓存不存在，生成视频时仍会先准备它。修改 V/A 同时可能使视觉规划需要更新，这与只改运动层不同。

## 导出的数值与实际画面

flow-v1 输出目录 `projects/p-*/renders/v-*/` 增加以下文件：

| 文件 | 内容与范围 |
| --- | --- |
| `motion_plan.json` | 配置、控制时间点、自动与生效帧、区间、解释和音频特征来源；保存整首计划 |
| `motion_plan.csv` | 按本次输出 FPS 采样的整首运动控制计划；片段生成也保留整首计划 |
| `frame_values.csv` | 真正输出的每帧控制，只有实际视频片段；与原始/生效情绪、视觉数值放在同一行 |
| `render.json` | 正式修订或预览快照身份、运动引擎、配置、音频特征键、环境和实际输出范围 |

`motion_mode` 是当前权重最大的模式；`motion_source` 区分 auto / manual / transition，`motion_reason` 描述规则或人工原因。`motion_speed`、`motion_radius` 等标量列只描述主成分的参数，不是混合后的单一物理速度，更不是所有粒子的实测平均速度。

要复核过渡，请查看 `motion_components_json`：里面保存实际送给渲染器的每个 `{mode, weight, params}`。`frame_values.csv` 还包含 `audio_rms`、`audio_onset`、`audio_activity`、`audio_pulse` 及最终 `beat_impulse`，后者结合已有节拍提示和音频脉冲。数据是控制输入，不是粒子坐标轨迹导出。

原始预测 CSV 中的 Energy 与这里的真实音频活动强度是两种不同数据，不可互相当作同一个指标。轻量音频特征缓存在项目新增的 `motion_features/`；算法与校验细节见 [音频运动特征说明](MOTION_FEATURES.md)。

## 兼容、复现与边界

- legacy 不进入新运动计算路径；切换引擎不会替换模型、重写原始预测或删除旧视频。
- 运动配置随修订、冻结预览和草稿历史保存；生成使用固定版本，不读取后续草稿。
- 相同输入、种子、配置和运行环境下，模拟以确定性规则推进；模式过渡、出生代数、固定粒子特征、随机状态与拖尾都属于检查点状态。
- 检查点区分修订、引擎代码、音频特征、画面尺寸、FPS 等配置。没有匹配检查点或检查点无效时，从前面重新推进，不能拼接不兼容状态。
- 修改某段运动可能改变之后的粒子位置和重生时机。“已经退出人工覆盖”只表示控制恢复自动，不承诺后续像素立即恢复原版。
- 不承诺不同 FPS、尺寸、依赖版本、硬件或不同视频编码过程产生逐字节一致的视频；数值计划与输出元数据用于追溯。

本文是使用与数据合同说明，不代表浏览器流程或真实音乐视频已经全部通过验收。实际已执行结果以 [验收记录](VERIFICATION.md) 和相应任务报告为准。
