## 已实施：生成控制与缓存（以下现状指开发前）

### 1. 分析取消慢、进度停留在阶段起点

- 现状：CLAP、BiLSTM内部缺少批次取消与任务进度回调。点击取消可能等待整段提取结束。
- 实施：增加可选回调，批前检查取消、批后报告进度；将正在取消状态从取消标记派生，避免多方覆盖任务JSON。
- 边界：模型加载或单个底层算子仍不能瞬时中断；界面明确显示“正在请求取消”。
- 验收：第一批后取消，第二批不执行；不发布最终缓存/项目；已有完整缓存保持不变。

### 2. 缓存依赖过宽且模型版本标识不足

- 现状：修改HUD/渲染代码也会改变CLAP缓存键；另一方面未将实际CLAP快照及预处理版本完整纳入键。
- 实施：拆分特征提取、情绪预测、视觉规划、最终渲染四类指纹；任务启动时固定指纹并记录到产物。
- 迁移：新键不盲用旧缓存，旧缓存只读保留；考虑提供显式校验迁移工具，不能直接改名冒充新缓存。
- 验收：只改HUD不重算CLAP；换音频内容、CLAP快照或预处理配置必须重算；纯视觉编辑复用规划。

## 已实施：长歌曲性能与预览（以下现状指开发前）

### 3. HUD历史轨迹重复绘制

- 现状：每帧遍历已出现的全部轨迹，整曲累计工作量接近平方增长。
- 实施：原始/生效轨迹分别维护增量历史图层；最近2秒高亮独立绘制；向后跳转时重建图层，避免未来轨迹残留。
- 验收：顺序播放累计处理点数近似线性；跳转与顺序播放到相同时间的图像一致；2秒高亮不变。
- 性能证据：同一首3分钟、10分钟歌曲对比总耗时与后半段帧耗时，报告机器和参数，不预先承诺倍数。

### 4. 片段预览仍需从开头模拟

- 现状：粒子状态有历史依赖，从中段开始导出仍会计算前面的状态。
- 实施：先完成阶段指纹，再设计粒子、随机源、时间、场状态的完整检查点；仅匹配相同修订/参数时复用。
- 验收：从检查点恢复与完整重放的数值和像素一致。低分辨率预览仍标为近似，不冒充正式输出。

## 结果质量与交付边界

### 5. 主观修订与模型准确率尚未区分评估

- 现状：现有模型来源包含规则伪标签；本次流程验收不能证明情绪识别准确率。
- 方案：保留模型原始值与人工修订双轨，增加修改原因/听感标注；取得独立人工标签后再做评估、校准和数据划分。
- 不应做：单纯放大数值后宣称准确率提升，或用同一首歌曲训练并当作独立测试。

### 6. 尚缺整首长曲与跨电脑交付验收

- 已有证据：两首真实歌曲各6秒片段、既有模型、原始/修订/恢复三轮有声MP4；原始音乐和模型哈希不变。
- 仍需：整首及长曲压力测试、磁盘不足/断电恢复场景、不同分辨率耗时、可安装启动器、依赖与FFmpeg许可清单。
- 当前交付仍是本机源码工作台，不是已验收的跨电脑安装包；不自动清理旧视频和缓存。
